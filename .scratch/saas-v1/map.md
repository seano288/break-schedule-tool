# Break-Scheduling SaaS v1
<!-- wayfinder:map -->

## Destination

A **buildable v1 spec** for a **CA-first, server-side-compute break-scheduling SaaS** — a document a builder (human or agent) can start from, with the strategic and architectural forks already resolved.

## Notes

**Domain:** Takes an hourly-worker shift schedule, computes CA-compliant meal periods and rest breaks (split-shift aware), and staggers breaks so coworkers in a department aren't out at once. The valuable IP is the `core/` algorithm.

**Skills to consult each session:** `/grilling` + `/domain-modeling` for decision tickets; `/research` (subagent) for research tickets; `/prototype` where "how should it behave/look" is the question.

**Constraints & governing principles (settled during charting):**
- **Only preserved asset:** the `src/core/` algorithm — moves server-side, reused verbatim. Everything else (current UI, Vite SPA, GitHub Pages deploy) is greenfield/disposable.
- **B1 compute-only:** the algorithm runs server-side (IP protection); employee data is transient — processed in memory, never stored.
- **Retail-only** for v1.
- **Seam principle:** a canonical schedule model + pluggable adapters at every edge — ingestion parsers, vertical rules, state rules. The core stays pure; all variation lives in adapters.
- **Infra principle:** prefer managed / off-the-shelf services over self-operated infrastructure, on every infra decision. Criterion: balance deployment/operational simplicity against cost.
- **Performance principle:** *design for simplicity, instrument well, optimise only on confirmed need.* Ship the simplest shape that works at expected scale; pair every deferred optimisation with a written numeric trigger **and** the instrumentation that would detect it. Corollary: **analytics/logging is a v1 requirement, not garnish** — the principle only holds if the confirming data is actually collected. (Already the implicit default in [#10](issues/10-set-per-request-size-ceiling.md); elevated to a governing principle during [#09](issues/09-define-compute-api-surface.md).)
- **IP posture (re-based during [#09](issues/09-define-compute-api-surface.md)):** protecting `src/core/` from *download* still matters; **resistance to reverse-engineering does not** — "what we're doing isn't rocket science." [#05](issues/05-draw-ip-protection-cut-line.md) is **not** reopened: its decision 4 (whole-core-opaque) stands on **drift** — client-side rule duplication becomes a compliance veneer over a subtle error ([#01](issues/01-audit-ca-compliance-completeness.md)) — not on secrecy, and decision 5's rate-limiter was already deferred by [#07](issues/07-decide-infrastructure-stack.md). Stop citing IP secrecy as grounds for future strictness; cite drift.
- **Data-retention posture (set during [#09](issues/09-define-compute-api-surface.md)):** B1's "never stored" is about **no long-term PII retention**, not a ban on all server-side state. Short-lived, encrypted-at-rest, promptly-expired intermediate storage (e.g. a KV parse cache) is **permitted** where it is a good engineering trade, provided the user-facing promise is worded to communicate honestly that we do not exploit their data.
- **Backend:** Node/TS serverless (reuses `core/` unmodified — no port).
- **Frontend:** greenfield, open decision.
- **Self-serve** SaaS, built on managed auth + billing services.
- **Multi-state:** an architectural constraint (state rules = a pluggable adapter), CA-only implemented in v1.

## Decisions so far

<!-- one line per closed ticket: gist + link -->

- [Research the scheduling-integrations landscape](issues/02-research-integrations-landscape.md) — **validates the upload-only bet.** Every major WFM/scheduling product (UKG, Workday, Deputy, When I Work, Homebase, etc.) offers a file export; **none has a self-serve API** (all need tenant + approval). So tabular-upload + UKG preset is sufficient v1 coverage. **Real risk = column-variance** (UKG columns are admin-configurable) → invest in robust column-mapping, not more formats. First post-v1 API parser: UKG Pro WFM, then Deputy. Never build to Kronos WFC (EOL).
- [Audit CA compliance completeness](issues/01-audit-ca-compliance-completeness.md) — **close but not correct.** Rest-break count + first-meal deadline verified right. **3 bugs, all on long/split shifts:** (B1 HIGH) shifts >10h silently drop the 2nd meal + 3rd rest (no `rest3`/`REST3` slot+column); (B2 MED-HIGH) split-shift gap accepted as meal with no timing check; (B3 MED) no impossibility detection. **v1 must-handle:** 5-break model + output cols, split-gap timing check, per-employee "can't comply" flag. **Defer:** meal waivers, §226.7 premium-pay math, split-shift premium. → unblocks the canonical-model ticket.
- [Research the managed-platform landscape](issues/03-research-managed-platform-landscape.md) — *informational, not a decision.* Recommends **Vercel + Clerk + Stripe** for simplicity (~$20/mo floor); runner-up **Cloudflare Pages + Workers + Clerk + Stripe** (~$5/mo, but Node-compat + bolt-on auth caveats). Feeds the fogged Infrastructure-stack decision. Traps flagged: Vercel free tier bans commercial use, Supabase forces ~$25/mo, Netlify Identity deprecated, Cloudflare Access ≠ consumer signup, Azure/AWS cheap-but-complex.
- [Draw the IP-protection cut-line](issues/05-draw-ip-protection-cut-line.md) — **thin client, whole pipeline server-side.** Parse boundary = **server-side (Option B)**: client uploads the *raw file*, server parses (in-memory, never stored — B1-safe); the canonical-model shape never crosses the wire. Mapping = **B-preset** (named presets + auto-detect, loud rejection of unmatched files); interactive **B-map** deferred to **v2**. Output = **R-server** (server renders styled xlsx + preview JSON; client is a thin shell). Granularity = **whole-core-opaque** — all of `src/core/` server-only as one unit, client duplicates zero rule logic (drift = the #01 failure mode). Bulk-extraction = **accept**: auth-gate + tiered abuse rate-limit (trials tighter) + anomaly logging + accept residual; output-perturbation ruled out (compliance tool); abuse ceiling ≠ usage quota (pricing = unlimited runs). → **unblocks the Infrastructure-stack decision** and hands #06 the constraint that the parser is server-side and the canonical model is a *server-internal* seam, not the wire contract.
- [Decide pricing shape](issues/04-decide-pricing-shape.md) — **linear per-location subscription.** Buyer = multi-location retail chain (fact: existing user is a chain), so value metric = **per-location** (not per-seat/per-run). Shape = one `per_unit` price × N locations, **monthly + discounted annual**. Location count is **self-declared** (an account attribute, B1-safe — never inferred from uploads); **runs/uploads unlimited & uncharged** (billing decoupled from parser and compute). Entry = **14-day trial, no card up front**, card at conversion. Deferred: tier banding, content-based enforcement, freemium. → hands the billing ticket its exact Stripe constraint.

- [Design canonical schedule model + parser interface](issues/06-design-canonical-model-and-parser-interface.md) — **the seam is a flat `Segment[]`; all domain reasoning sits behind it in `core/`.** Reframing: `core/` was *never* decoupled — `scheduleBreaks` took the raw sheet grid and parsed it internally, so this cut the parser **out** of `core/` and moved day-splitting **in**. Model = `{employeeId, employeeName, workdayDate, dept, job, start, end}`, one record per source row. Decisions: (1) parser flattens layout state, **core** owns identity/grouping/workday-partitioning/split-shift detection — mis-grouping is compliance-relevant, so it gets one audited home; (2) **`employeeId` required, file rejected without it** — today's name-keyed identity merges two same-named employees into a fabricated split shift that *cancels a required meal*; (3) **day-anchored minutes, `end` may exceed 1440** — fixes a live bug where a 10PM–6AM shift yields `totalWorkMinutes = −960` and therefore **zero breaks**; keeps `core/`'s minute thresholds "verbatim"; v1 *flags* cross-midnight rather than applying §500; (4) **no provenance — output rendered fresh** from canonical + results, reusing the existing stylers (they take `(sheet, rows)`); removes `rowIndex` from `core/`, lets the upload be discarded (B1), kills `deleteColumnD`; (5) **one code module per format** (`detect`/`parse` + rejecting registry), no shared column-map DSL from n=1 — so **B-map v2 is a new parser**; (6) **tiered errors** — fatal → reject upload; an unparseable employee row **poisons that employee-day** (reported, not silently short-houred); by-rule skips silent. Fell out: **one exception channel** for `CANNOT_COMPLY` + `OVERNIGHT_UNSUPPORTED` + `SOURCE_ROW_UNPARSEABLE`, and **five named break slots** so #01's B1 collision is unrepresentable. → raises **#08**.

- [Decide the infrastructure stack](issues/07-decide-infrastructure-stack.md) — **Cloudflare Pages + Workers + Clerk + Stripe** (recorded as [ADR-0001](../../docs/adr/0001-cloudflare-pages-workers-for-compute.md), which carries the platform's limitations). Billing provider settled as **Stripe**, knowingly accepting merchant-of-record status and therefore **owning US multi-state SaaS sales-tax registration/remittance** (an MoR would have absorbed it) in exchange for ~$56/yr lower fees, full control of the `per_unit` quantity model, and the **ACH lever** (0.8%, capped $5). Overrides #03's top pick by *measurement*: its two objections to Cloudflare both collapsed — **Node-compat is falsified** (`src/core/` imports nothing but its own files and touches zero Node/browser globals; SheetJS already runs in browser V8 today with **no polyfills**, so the whole pipeline is pure-V8), and "auth is a bolt-on" never differentiated (Vercel bolts on the same Clerk). Every Workers ceiling measured with headroom: bundle **0.3 MB / 10 MB**, CPU **~1 s / 30 s**, body **tens of KB / 100 MB**. Won on 4× cheaper ($5 vs $20), a bigger body limit for an upload product, and native Rate Limiting + KV for the deferred limiter; **knowingly accepted** the residual risk of a *future* dependency needing real Node. Three scope decisions fell out: (1) **v1 rolls out invite-only**, so the abuse-limiter is deferred — the invite gate is the v1 mitigation and the limiter is the **price of opening the gate**; (2) the beta is a **rollout mode of v1, not a smaller v1** — full self-serve product ships with billing **dormant**, keeping #04 intact; (3) **one request = one location-week**, which bounds the newly-measured **O(n²·³)** cost of `core/` to ~130 ms per store-day and is *why* the Workers CPU ceiling is safe. Build constraint: `enableLogging` defaults **on** and must be forced off server-side. → raises **#09**, **#10**; unblocks the **billing-provider** and **frontend-architecture** fog.

- [Confirm the UKG export can emit an employee-id column](issues/08-confirm-ukg-employee-id-column.md) — **admin-configurable only, and the premise was wrong.** The anchor file is **not** a Schedule Planner export but a **customer-authored custom BIRT report** (Report Library → Custom Reports → Custom Daily Schedule — our own `UkgMock.js` walks exactly that), so its columns are by construction the customer's own report design and **no public column inventory exists for any of it** — #02 could never have closed this. **Not default:** the real file is five columns, name-keyed, no id; every UKG-*delivered* schedule report is name-only too, so **the anchor customer's export would be rejected by #06's invariant today.** **Not unavailable:** the identifier exists at every layer (`personNumber`/`personKey`/badge, Dataview's *Employee ID*, and *Good Faith Estimate* renders it). UKG closes the question in one sentence: manager column show/hide "will not be applied the next time they run a report… persistent changes… by the **Administrator in report studio**"; run params are Timeframe/Hyperfind/Output-Format only, and `CSV_Export_Column_Names_Order` sets *order*, not membership. So the prerequisite is an **admin report re-design with lead time** (Report Studio → Table Builder → republish → re-assign Report Data Access Profile), worst case a UKG Salesforce SR — **not a tutorial step, and it lands on a different person.** Three things fell out: (1) the fog item is re-pointed off "Schedule Planner"; (2) #06's rejection copy asks the manager to do something they *cannot*; (3) **"the admin who won't" is not hypothetical — the anchor customer is in that state now**, raising **#11**. Also: a **blank cell in a present id column** must be `SOURCE_ROW_UNPARSEABLE`, never a valid empty key (vendors often ship the id as optional/employer-populated); **Deputy/When-I-Work schedule exports are equally unconfirmable** from docs (zero published column lists across three vendors — vindicating #06's loud rejection), Deputy's shift-grain interchange format matches on **email** with no id at all, and every vendor's **API** does carry a stable shift-level id — a second reason #02 put the UKG Pro WFM API first: **the API is the only ingestion path where identity is guaranteed rather than negotiated.**

- [Define the compute API surface](issues/09-define-compute-api-surface.md) — **two endpoints confirmed — but only after closing a hole in the canonical model.** The ticket's premise was false: [#06](issues/06-design-canonical-model-and-parser-interface.md)'s `Segment` has **no `location` field** and its parser ignores the UKG `Location:` row, yet #07 and #10 both assume a `(location, workday)` partition. Not cosmetic — coverage groups key on `dept`/`job`, so two stores both having `Frontline/Cashier` become **one coverage pool** and breaks get staggered between employees who never share a building. So: **`location` joins `Segment`** (required, non-null — #06 amended), with **three-tier sourcing** (per-row column / `Location:` row naming one store / assumed) and an **advisory notice on tier 3 only** — advisory because a merged pool degrades *quality*, not legality (meal placement is bounded to its legal window *before* the optimizer runs, `BreakScheduler.js:193-199`), and because the single-location manager is a real customer who must not be blocked. **The surface:** `POST /inspect` (raw file → preset, locationSource, locations+counts, **departments**, notices, exceptions, or fatal) then `POST /schedule` per location-week (→ xlsx, previewJson, exceptions). Forced by two things only: the client **cannot express `settings.groups` without a parse** (departments come from the file — so #05's single POST is unsendable by a first-time user), and per-location-week granularity is what keeps compute inside the Workers ceiling (~0.9 s vs ~45 s for a 50-store week). **`/inspect`'s ceiling = "only data already in the customer's file", re-based off secrecy onto drift** — the argument #05's decision 4 actually rested on; refuse "return total hours"/"who needs a 2nd meal"/"suggested times" against it, since together they rebuild `core/` in the browser. **Re-upload per location for v1**, KV handle deferred-not-rejected with a written **~20-location trigger** (forward-compatible: `uploadRef` is addable later). **Bounded fan-out (~4) with partial success first-class** — 8 of 10 yields 8 workbooks; the UI owes a *loud, persistent* failure summary. **Exceptions in both channels** from one array, and a poisoned employee-day is a **visible row carrying the reason**, never omitted (today `ExcelFacade.js:176-178` writes blanks, indistinguishable from "needs no breaks"). **Both endpoints Clerk-gated** with one `requireEntitlement()` helper — validated and tested, permissive by config during the beta. **Size ceiling advisory at `/inspect`, binding at `/schedule`, failing one location** — and it doubles as the detector for the merged-multi-location case tier 3 can't see. Structural finding: **a document-level notice channel is now needed** (#06's is per-employee-day; both this and #11 want per-document). → raises **#12**; hands #10 its enforcement point; unblocks the **Frontend architecture** fog.

## Not yet specified

- **Billing config** — provider now **settled: Stripe** (see Decisions); pricing *shape* settled by #04; infra blocker cleared. What remains is the concrete config, ready to graduate: the `per_unit` price object with quantity = self-declared locations, monthly + discounted annual, 14-day trial with no payment method, self-serve quantity control, the webhook→entitlement path, and whether **Clerk Billing** can serve it at all — **it bills per org *member*, but the value metric is *locations***, and a 10-location chain may have 3 logins, so that mismatch must be verified rather than assumed.
- **US multi-state SaaS sales-tax registration & remittance** — created by choosing Stripe over a merchant-of-record (Paddle would have absorbed it). Stripe Tax calculates but does not register or file. Dormant during the invite-only beta; **must be discharged before the first real charge**. Too coarse to ticket until the beta cohort and first customer states are known.
- **Frontend architecture** — framework/shape of the greenfield client. Both blockers now **cleared**: hosted on **Cloudflare Pages** with **Clerk** drop-in components (#07), and [#09](issues/09-define-compute-api-surface.md) has fixed the contract it is written against. **The existing UI is explicitly disposable** — the current wizard's step order is not a constraint on the new design. Shape: a thin shell over **upload → `/inspect` → configure → `/schedule` × N**, holding settings client-side (no v1 persistence) and shipping none of `src/core/`. #09 hands it four concrete obligations: the **department inventory arrives from `/inspect`**, so the coverage-group UI is gated on a successful upload; **bounded-concurrency fan-out (~4)** over locations; **independent per-location row states** (`pending → done → download` / `failed → reason → retry`); and a **loud, persistent partial-failure summary** ("8 of 10 locations scheduled…") — named in #09 as the accepted cost of partial success and therefore a UI obligation, not an optional nicety. Also renders the **document-level notices** (tier-3 location assumption) alongside per-employee-day exceptions. Ready to graduate.
- **Onboarding / export-tutorial rewrite** — surfaced by the canonical-model decision (`employeeId` is **required**) and now re-pointed by [#08](issues/08-confirm-ukg-employee-id-column.md): the walkthrough (`ExportHelpStep.js`, the 500-line `UkgMock.js` click-through) targets a **customer-authored custom BIRT report in the Report Library**, not Schedule Planner, and the id column needs an **admin report re-design with lead time** — so the tutorial cannot *teach* adding the column. Its job shrinks to **verifying** the column is present and **naming the ask precisely** (report, field, role) for the internal IT/HR ticket; `ExportHelpStep.js`'s existing "Manager or admin access required" callout is where that prerequisite hangs, and #06's rejection copy must stop asking the manager to do something they cannot. Shape now waits on [#11](issues/11-decide-missing-employee-id-fallback.md), which decides whether there is a no-admin path at all.
- **v1 feature-scope lock + spec assembly** — the final synthesis that produces the destination artifact; blocked by ~all upstream decisions, now including [#10](issues/10-set-per-request-size-ceiling.md), [#11](issues/11-decide-missing-employee-id-fallback.md) and [#12](issues/12-define-observability-without-pii.md). Carries one item that belongs to no single ticket: the **document-level notice channel** (#06's exception channel is strictly per-employee-day; [#09](issues/09-define-compute-api-surface.md)'s tier-3 location notice and #11's prospective identity provenance both need a per-document block).
- **Beta invite/rollout mechanics** — v1 ships as an **invite-only beta** with billing dormant. Who gets invited, how invites are issued and tracked, and the explicit checklist for flipping the gate open (which includes landing the deferred abuse-limiter). Too coarse to ticket until the beta cohort is known.

## Out of scope

- Food-service (and any non-retail) vertical — seam designed for it, not built.
- Multi-state rules beyond CA — architecture allows it; not implemented in v1.
- Server-side persistence / schedule history / audit records (the B2 model).
- Direct API integrations — v1 is upload-only.
- JSON / non-tabular ingestion parsers.
- The existing free `kadencampb.github.io` tool — a disposable college assignment; no migration, no carryover.
- Interactive per-file column-mapping UI (**B-map**) — v1 ships preset-based mapping only (B-preset) with loud rejection of unmatched files; interactive mapping is a **v2** fast-follow. See [the IP-cut-line decision](issues/05-draw-ip-protection-cut-line.md). **Amended by [#06](issues/06-design-canonical-model-and-parser-interface.md):** since parsers are per-format code modules with no shared column-map abstraction, B-map arrives as a **new parser**, not as a preset instance reusing the v1 seam.
- Cross-midnight (overnight) shift rules — the canonical model *expresses* them (`end` may exceed 1440) and v1 **flags** them as unsupported per employee, but CA §500 workday-spanning rules are not applied. Deliberately deferred to v2; no model migration needed then. See [#06](issues/06-design-canonical-model-and-parser-interface.md).
- **Tiered per-account abuse rate-limiting + anomaly logging** — required by [#05](issues/05-draw-ip-protection-cut-line.md), deferred out of v1 by [#07](issues/07-decide-infrastructure-stack.md) because **v1 rolls out invite-only** and the vetted-invite gate is the v1 mitigation. **Not optional later: it is the precondition for opening the gate to self-serve signup.** #05 is re-based, not reopened. Cloudflare's native Rate Limiting binding + KV make it cheap to land when owed.
- Carrying the customer's own extra columns / formatting through to the output — v1 renders a fresh document from the canonical model instead of annotating the upload. See [#06](issues/06-design-canonical-model-and-parser-interface.md).
